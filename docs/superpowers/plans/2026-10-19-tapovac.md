# TapoVac-ADV support

Goal: consume the existing local TapoVac-ADV HA integration safely, so the RV50 tester can supply useful area/time/water-setting telemetry without VWM implementing TPAP.
Architecture: registry-scoped `tapo_rv30` descriptor, vacuum attribute counters, explicit mopping mode, existing accounting and calibration. No protocol calls or robot commands.
Tech stack: Python HA integration and existing JS card.
Spec: issue #10 and Maciej's 19 October request to plan, implement and test support. Upstream jan-tdy/TapoVac-ADV pinned 887050da97aa63db1ca0fd39b7d61aa97a9bf796; cavefire/tapo-vacuum-ha pinned 265a24f9f17536a646d18efaa57bdcbd428d9009.

## Global constraints

No invented water coefficients, direct-volume claims, wash counters or physical accuracy. Attachment and a non-off water setting do not prove mopping. Mapping (raw status 2) is never water-consuming. Separate Matter/native registry devices are never merged by model/name. Existing explicit duplicate linking keeps one history owner and does not import signals. The user may explicitly configure a Matter cleaning-mode entity only after confirming the physical robot. No private HA or physical robot mutations. Public release requires separate coordinator grant.

## Review Focus

Upstream defaults can hide missing raw telemetry; select labels may look metric even on unsupported raw codes. No unrelated entity may establish units or mode automatically. A static setting or hardware attachment cannot activate billing. Mapping and unknown status must not be interpreted as cleaning. One explicitly linked physical robot must have one owner. Dock settings/capabilities are not actual wash events.

## Implementation rulings

- Existing Notion #10 decision dated 15 October requires normal full-tank learning without asking users for manual measurements. Native counter support therefore retains that workflow: observed minute-counter exposure, three compatible tanks, separate context from Matter, no copied bank or class prior. Floor-only ml/m² and independent dock doses remain unverified until their physical data exists. This preserves the user outcome while keeping unknown physics explicit.
- Fresh review found attribute-backed area recovery could charge twice and water-level attributes were absent from calibration context. Both require RED/GREEN regressions and generalized attribute parity before native QA.
- Real HA settings changes rebaseline accounting and refills clear counters. Fixtures must start a newly observed session after refill, through ordinary events, rather than expecting old exposure to remain chargeable.
